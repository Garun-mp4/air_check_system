# Поправка №1 к ТЗ

Дата: 2026-09-06

## Приоритет

Эта поправка внесена по прямому указанию заказчика и заменяет требования исходного ТЗ к языку и framework backend/frontend в части, где указаны Go/Gin и чистый HTML/CSS/JavaScript.

## Актуальный стек

- сервер и REST API: TypeScript + Next.js server route handlers;
- frontend: React + TypeScript в приложении Next.js;
- база данных: PostgreSQL;
- ML-сервис: Python + scikit-learn;
- simulator: Python, HTTP/JSON;
- обмен между simulator, TypeScript server и ML: REST/JSON;
- UI-стили: токены и компоненты из DESIGN-cal.md, реализованные в React/CSS.

Next.js выбран потому, что это React-фреймворк с полноценным серверным runtime: API Route Handlers выполняют роль backend-сервера, а React-компоненты — роль frontend. Это сохраняет требование о едином TypeScript/React-приложении, не вводя отдельный backend framework.

В docker-compose service backend собирает это Next.js-приложение и одновременно предоставляет React UI и REST API на порту 3000; отдельный статический frontend-сервис не нужен.

## Что не меняется

- PostgreSQL и таблицы measurements, predictions, recommendations;
- обязательные endpoint и формат измерения от будущей ESP32;
- feature engineering, временное разбиение train/test, Linear Regression, Random Forest, MAE и RMSE;
- rule-based Recommendation Engine и пороги CO₂;
- simulator с режимами normal, closed и open;
- требования к состояниям loading/error/empty, графикам и responsive UI;
- исключённые из этапа функции: физическая ESP32, MQTT, Telegram и авторизация. Автоматическое управление окном, вытяжкой и притоком добавлено последующей поправкой №3.

Поправка №3 имеет приоритет в части климатического контура и заменяет прежнее исключение автоматического управления.

## Актуальная схема

~~~text
Sensor Simulator / future ESP32
              ↓ REST / JSON
Next.js TypeScript Server (React UI + API Route Handlers)
              ↓
          PostgreSQL
              ↕
       Python ML Service
~~~

Публичный контракт POST /api/v1/measurements остаётся неизменным, поэтому последующая замена simulator на ESP32 не требует переписывать сервер, ML или dashboard.
