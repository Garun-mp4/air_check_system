# AirCheck: прошивка одной ESP32

Цель — DevKitC V4 / WROOM-32E, 4 MB flash. Пины генерируются из [hardware.json](../../config/hardware.json). SDK: ESP-IDF 6.1.0, PlatformIO Core 6.1.18 / espressif32 7.1.3, cJSON 1.7.19~2. Драйверы используют официальные команды Sensirion; окончательная приёмка требует настоящих датчиков.

Четыре задачи датчиков независимы (I²C имеет ограниченный таймаут). Цикл управления каждые 20 ms имеет приоритет выше чтения и сети. HTTP выполняется отдельно, с проверкой CA/имени и ограничением ответа; перенаправления запрещены. Sampler формирует неизменяемые пакеты с boot_id/sequence. Очередь в RAM ограничена восемью пакетами; переполнение учитывается в диагностике, а отказ сети не задерживает управление. Подтверждение привода требует концевика, вентилятора — тахометра. Время хода ограничено 30 s; противоречивые концевики и отсутствие RPM фиксируют отказ. Промежуточный процент не вычисляется по времени. После fault требуется осмотр и перезапуск; автоматического бесконечного повторения нет.

## Сборка и тесты

```text
python -m pip install -r firmware/requirements-build.txt
python firmware/esp32/generate_board.py --check
python firmware/esp32/build.py --env esp32
python firmware/esp32/build.py --env fake
python -m pytest tests/firmware tests/infrastructure/test_hardware_contract.py -q
```

На Windows `build.py` временно копирует исходники в короткий ASCII-путь `C:\acbuild`, поскольку ESP-IDF отвергает пробелы, а Windows ограничивает длину shell-команды. Путь можно задать через `AIRCHECK_BUILD_ROOT`. Hook `windows_ldgen.py` вызывает только длинную команду ldgen через CreateProcess, сохраняя аргументы SDK. Исходники/секреты временной копии удаляются после сборки. Артефакты находятся в `.pio/staged/<env>` и исключены из Git. Native-тесты исполняют C++-ядро с ASan/UBSan через установленный g++ или Docker gcc:14.

`fake` генерирует явно помеченные simulator-данные, исполнительные выходы всегда запрещены. Это не эмуляция физического подключения настоящих датчиков. В обычном варианте выходы также остаются запрещены, пока в NVS явно не установлено `commissioned=1`. Перед этим проверить питание, драйверы, внешние подтяжки, активный LOW концевиков, два импульса тахометра на оборот и фактический предел хода. Контакты не позволяют однозначно отличить каждую неисправность проводки от состояния механизма; не считать GPIO доказательством исправности.

## Локальная конфигурация

Основной способ — NVS namespace `aircheck`: строки `ssid`, `password`, `server`, `device_id`, `token`, `root_ca`, `ntp_server`; u8 `commissioned` (по умолчанию 0). Необязательный `include/secrets.h` повторяет шаблон `secrets.example.h` и исключён из Git. Корневой сертификат берётся из конкретной установки Caddy. Нельзя подменять его отключением проверки TLS. `ntp_server` по умолчанию совпадает с именем HTTPS-сервера; он должен предоставлять SNTP в локальной сети на UDP123, чтобы синхронизация не зависела от внешнего интернета.

Создать закрытый JSON вне Git с полями `ssid`, `password`, `server` (HTTPS origin), `device_id`, `token` (от 32 символов), `ca_file` (путь относительно JSON к корневому PEM), `commissioned: false`. Для генерации использовать Python с установленными requirements-build.txt (включает официальный esp-idf-nvs-partition-gen 0.3.0):

```text
python firmware/esp32/provision.py --config <private.json> --idf <framework-espidf> --out <private-nvs.bin>
```

Команда создаёт NVS-образ 0x6000 байт, ничего не прошивает и не печатает значения секретов. Для конкретной платы после проверки подключения прошить bootloader по 0x1000, partitions по 0x8000, конфигурацию NVS по 0x9000 и firmware по 0x10000. Не стирать NVS автоматически: ошибка инициализации оставляет сеть выключенной, локальные ограничения продолжают действовать. Бинарник конфигурации содержит секреты и не предназначен для публикации.

До синхронизации часов удалённые команды не исполняются. Повторный ID не запускает движение заново; истечение и исчезновение команды из серверной очереди останавливают незавершённое действие. После 90 s отсутствия успешной связи с сервером доступна локальная вентиляция по достоверному CO₂ и безопасным наружным данным с гистерезисом 1000/800. Ручной запрос сохраняет локальный override на 30 min. Недостоверные наружные/внутренние данные останавливают неопределённое движение и вентиляцию; закрытое окно не предполагается без обратной связи. Локальное поведение нужно согласовать с выбранными нагрузками и проверить на стенде.

Протокол отправки — `/api/v1/telemetry`, schema_version=2. Интеграция серверного обработчика и постоянного реального 3D выполняется следующим этапом; одна успешная сборка не означает готовность всего контура. Необязательный SD-журнал и экспорт модели входят в отдельные пункты общего плана.

Основания команд: [SCD4x driver](https://github.com/Sensirion/embedded-i2c-scd4x), [SHT4x driver](https://github.com/Sensirion/embedded-i2c-sht4x), [SPS30 UART](https://sensirion.com/resource/datasheet/sps30), [PlatformIO releases](https://github.com/platformio/platform-espressif32/releases), [ESP-IDF 6 migration](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32/migration-guides/release-6.x/6.0/protocols.html).
