# Демо-сценарии

## Сценарии окружения

| Сценарий | Что демонстрирует |
|---|---|
| Normal Room | исходный комфортный режим |
| CO₂ Buildup | рост CO₂ в закрытой комнате с occupancy |
| High Occupancy | ускоренный рост загрязнителя от людей |
| Clean Outdoor Air | проветривание чистым наружным воздухом |
| Polluted Outdoor Air | поступление PM2.5 через окно и эффект фильтра |
| Cold Weather | охлаждение комнаты при наружном холоде |
| High Indoor PM2.5 | внутренний источник частиц и очистка |
| Sensor Failure | недоступность виртуального датчика и обработка неполных readings |
| Backend Offline | UI offline-состояние без остановки физики |

Параметры задаются в `config/demo.toml`. Выбор сценария сбрасывает indoor/outdoor состояние, среду, окно и вентиляторы к его начальным условиям. Для выхода из Backend Offline выберите другой сценарий.

## AUTO DEMO

Автоматическая демонстрация проходит этапы:

1. Simulator сбрасывает сценарий CO₂ buildup и повышает occupancy.
2. Фиксированная модель накапливает CO₂; Virtual Sensors публикуют новые значения.
3. Backend сохраняет telemetry и возвращает ML forecast, если модель доступна.
4. Backend automation создаёт commands; Simulator только получает их.
5. Device Layer включает fans и физически открывает створку до концевика.
6. Actual state отправляется с command IDs; backend принимает ACK.
7. Модель airflow снижает концентрацию, UI завершает demo после настроенного падения CO₂.

Для полного прохода нужны доступный backend, активная автоматика, обученная ML-модель и корректный `device_id`. `wind_speed_m_s = 3.0` в сценарии CO₂ buildup оставляет комнату закрытой во время накопления, но создаёт воспроизводимый воздухообмен после открытия окна.

Если backend недоступен, demo остаётся на этапе телеметрии/прогноза, показывает offline-статус, а local physics работает. Simulator не генерирует поддельный forecast и не подменяет backend-команду локальной автоматикой.
