# Архитектура AirCheck 3D Simulator

## Поток состояния

```text
SimulationEngine ──> SimulationState ──> VirtualSensors ──> telemetry
       │                    │                                  │
       └──> DeviceLayer ────┴──> Presentation/UI               ▼
                                                NetworkIntegration
                                                        │
                                                        ▼
                                               AirCheck REST API
```

`SimulationState` — единый текущий снимок комнаты, датчиков, контроллера, окна, вентиляторов, воздушного потока и энергии. `SimulationEngine` выполняет фиксированные шаги: сначала Device Layer продвигает исполнительные механизмы, затем `RoomModel` пересчитывает среду. `VirtualSensors` читают измерения из этого состояния.

## Границы слоёв

- `app/` загружает TOML-конфигурацию, создаёт компоненты, связывает пользовательские действия и управляет временем жизни приложения.
- `simulation/` содержит состояние комнаты, фиксированные часы, расчёт среды и виртуальные readings. В расчётах нет зависимости от графического FPS.
- `devices/` владеет actual state окна, концевиками, герконом и вентиляторами. `DeviceCommandExecutor` принимает команду, применяет её через Device Layer и ждёт фактического состояния.
- `networking/` выполняет HTTP в одном управляемом фоне-потоке. Очереди событий передают результаты главному потоку; фоновый worker не вызывает Panda3D и не мутирует simulation state.
- `scene/` строит комнату и low-poly компоненты. `presentation/` связывает устройства с визуальными объектами, управляет камерой, вводом, picking и airflow.
- `ui/` только отображает актуальные снимки Simulation Core, Device Layer и backend.

Сцена не принимает решений автоматики. Решение остаётся в AirCheck backend, а Simulator применяет полученную команду и отчитывается о фактическом результате.

## Частоты и потоки

| Подсистема | Частота или правило |
|---|---|
| Рендер Panda3D | ограничен `graphics.target_fps`, по умолчанию 60 FPS |
| Simulation Core и Device Layer | фиксированный шаг 0,1 с, 10 Гц; множитель времени настраивается отдельно |
| HUD и панели | интервал обновления 0,1 с, 10 Гц |
| Камера, hover/picking и визуальные привязки | обновляются задачами Panda3D на кадр |
| Network Layer | отдельный поток; таймаут, retry, polling, telemetry и health задаются в `backend.toml` |

Если кадр задержался, физика догоняет накопленное время ограниченным количеством шагов на кадр и переносит остаток. Она не меняет размер физического шага.

## Запуск и завершение

`python -m aircheck_simulator_3d` читает девять файлов `config/*.toml`, настраивает ротационные журналы, создаёт Panda3D window, запускает NetworkIntegration и runtime. При закрытии runtime удаляет задачи и клавиатурные события, сетевой поток получает сигнал остановки и ожидает завершения в пределах сетевого timeout, затем освобождаются UI, scene и renderer.

В standalone-сборке конфигурация включена в соседнюю папку `aircheck_simulator_3d/config`; изменяемые журналы записываются в `%LOCALAPPDATA%\AirCheck3D`.
