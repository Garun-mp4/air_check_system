# Математическая модель

## Модель помещения

Используется однозонное хорошо перемешанное помещение объёмом `V`. Для каждого загрязнителя применяется баланс источников и воздухообмена. При постоянных параметрах интегрирование первого порядка выполняется аналитически за фиксированный шаг `dt`, без случайного дрейфа:

```text
CO₂:   dC/dt = G/V + (Q/V) · (Cout − C)
PM2.5: dP/dt = S/V + Qin·Pin/V − (Qout/V + kdep)·P
Тепло: Cth·dT/dt = (UA + ρ·cp·Q)·(Tout − T) + N·Hperson
Влага: dw/dt = Gw/m_air + (Q/V)·(wout − w)
```

`G` задаётся генерацией CO₂ на человека и occupancy, `S` — внутренним источником PM2.5, `kdep` — осаждением, а фильтр снижает только PM2.5 наружного притока. Если вытяжка выше притока, недостающий объём компенсируется наружным воздухом. Сбалансированные вентиляторы не считаются дважды.

Расход через окно — оценка по давлению ветра и температурному напору:

```text
Qwindow = 3600 · Cd · Aeff · sqrt(2·Δp/ρ)
Δp = 0.5·ρ·Cwind·v²·|cos(θ)| + ρ·g·H·|ΔT|/(2·Tmean)
```

Эффективная площадь изменяется по фактическому углу створки и ограничена коэффициентом и максимальным расходом. Fans задают механический обмен, а их электроэнергия рассчитывается по мощности, доле оборотов и КПД. Отдельно накапливаются оценочные теплопотери при вентиляции.

Влажность переводится в влагосодержание, обновляется балансом влаги и переводится обратно в относительную влажность по насыщенному давлению пара. CO₂, PM2.5, RH, температура, airflow и энергия проверяются на конечность и физические границы.

## Время и воспроизводимость

Размер шага по умолчанию 0,1 с. Рендер ограничен 60 FPS, но simulation timestep не меняется. Множитель 1×–60× определяет, сколько фиксированных шагов сделать относительно прошедшего реального времени. Sensor noise — отдельная опция виртуального сенсора; основная физическая модель детерминирована.

Значения комнаты находятся в `config/room.toml`, параметры узлов в `config/devices.toml`, коэффициенты модели и timestep — в `config/physics.toml`. Сценарии и пределы Debug Panel — в `config/demo.toml`.

## Область применимости

Это лёгкая модель для проверки причинно-следственных трендов и демонстрации управления, а не CFD, калиброванная инженерная модель или прогноз энергопотребления. Она не моделирует стратификацию, несколько зон, открывание двери, HVAC, солнечный приток и аэродинамические характеристики конкретного окна. Для проектных расчётов коэффициенты нужно калибровать на реальном стенде.
