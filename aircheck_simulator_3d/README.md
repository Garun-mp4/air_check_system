# AirCheck 3D Simulator

Отдельное Python-приложение цифрового двойника AirCheck. В нём есть интерактивный 3D-стенд оборудования и детерминированная инженерная модель одной хорошо перемешанной комнаты. Обмена с backend на этом этапе нет.

## Запуск в Windows PowerShell

Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r aircheck_simulator_3d/requirements-dev.txt
.\.venv\Scripts\python.exe -m aircheck_simulator_3d
```

Короткая проверка старта и закрытия окна:

```powershell
.\.venv\Scripts\python.exe -m aircheck_simulator_3d --smoke-test-seconds 5
```

Для кириллических подписей используется системный TrueType-шрифт. Его путь задаётся в `config/graphics.toml` параметром `ui_font_path`.

## Управление сценой

| Управление | Действие |
|---|---|
| `W / A / S / D` | Плавное свободное перемещение относительно направления камеры |
| `Q / E` | Движение вниз / вверх по мировой вертикали |
| `Shift` | Ускорение перемещения |
| Зажать `ПКМ` и двигать мышь | Поворот камеры с захватом курсора |
| Колесо мыши | Плавный наезд / отъезд вдоль направления взгляда |
| `ЛКМ` | Выбрать объект сцены или снять выбор пустым щелчком |
| `F` | Плавно сфокусироваться на выбранном объекте |
| `R` | Вернуть камеру в начальную позицию |
| `C` | Переключить переднюю стену: видимая → прозрачная → скрытая |
| `O` / `K` | Подать локальную команду открыть / закрыть окно |
| `I` / `X` | Переключить локально приточный / вытяжной вентилятор |
| `V` | Включить / выключить фильтр притока |
| `Space` | Пауза / продолжить симуляционное время |
| `1`…`6` | Скорость времени: 1× / 2× / 5× / 10× / 30× / 60× |
| `Esc` | Освободить мышь и открыть подсказку; повторное нажатие продолжает работу |

На наведение указывает цветовой маркер курсора. Выбранный узел остаётся выделенным, а справа показывается его описание. Передняя стена в начальном режиме прозрачная, чтобы сразу был виден интерьер. Клавиши `O`, `K`, `I`, `X` и `V` меняют состояние только локального Device Layer; команды backend пока не подключены. Текущая скорость симуляционного времени показана слева.

## Архитектура приложения

- `scene/scene_builder.py` строит основание, пол, потолок, стены и наружную площадку, затем подключает сборку оборудования.
- `scene/device_models/` независимо собирает створку и привод, внутренние и наружные датчики, оба вентиляционных канала, технический шкаф и кабельные трассы из процедурной low-poly геометрии.
- `devices/window_actuator.py` и `devices/device_layer.py` владеют фактическим положением окна, мотором, герконовым состоянием, концевиками и состояниями вентиляторов.
- `app/runtime.py` обрабатывает локальные тестовые команды и масштабы времени, а `simulation/engine.py` выполняет фиксированные шаги независимо от render FPS.
- `simulation/room_model.py` рассчитывает воздухообмен, CO₂, PM2.5, температуру, относительную влажность и оценку энергии; 3D-слой получает только состояния устройств для отображения.
- `presentation/device_bindings.py` отражает фактический угол створки, индикаторы концевиков и вращение включённых вентиляторов; модели не содержат бизнес-логики.
- Провода различают питание (+12/+5 V), GND, связь датчиков (I²C/UART) и управление исполнительными устройствами. Это визуальная схема подключения, а не электрический CAD.
- `scene/objects.py` содержит процедурную геометрию и единый реестр интерактивных объектов.
- `scene/cutaway.py`, `scene/picking.py` отдельно управляют состоянием стены и raycast-выбором.
- `scene/lighting.py` настраивает ambient и directional light; при доступности драйвера включает карту теней.
- `presentation/camera_controller.py` отвечает за плавное перемещение, обзор мышью, наезд, фокус и сброс камеры.
- `presentation/input_controller.py` связывает действия клавиатуры и мыши с компонентами представления.
- `presentation/viewport.py` собирает слои, обновляет viewport и пишет оценку FPS при завершении.
- `ui/scene_overlay.py` показывает управление, режим стены, наведение и описание выбранного объекта.
- `config/room.toml`, `devices.toml` и `physics.toml` задают начальные условия и коэффициенты модели; `scene.toml`, `camera.toml` и `graphics.toml` описывают стенд, камеру и освещение.

Передняя стена отключает свою collision-маску в прозрачном и скрытом режимах, чтобы луч выбора проходил к объектам комнаты. Геометрия сделана процедурными кубами без дополнительных 3D-ресурсов.

Panda3D использует стандартные материалы с диффузным и зеркальным откликом, MSAA при доступности framebuffer и встроенные shadow maps. Модели оборудования процедурные и достаточно детализированы для архитектурной демонстрации, но не являются производственными CAD-моделями. Вращение вентилятора следует за состоянием устройства. Если драйвер не предоставляет MSAA, приложение продолжает работу без него.

## Математическая модель помещения

Среда считается однозонной и хорошо перемешанной. При расходах воздуха `Q` в м³/с и объёме `V` в м³ используются балансы:

```text
CO₂:      dC/dt = G/V + Q/V · (Cout - C)
PM2.5:    dP/dt = Sin/V + Σ(Qin · Cin)/V - (Qout/V + kdep) · P
Тепло:    Cth · dT/dt = (UA + ρ·cp·Q) · (Tout - T) + N · Hperson
Влага:    dw/dt = Gw/m_air + Q/V · (wout - w)
```

CO₂, PM2.5 и влагосодержание интегрируются точным решением баланса первого порядка за каждый фиксированный шаг: источники добавляют массу/концентрацию, воздухообмен стремит её к наружному значению, а фильтр уменьшает только наружную PM2.5 в приточном канале. При вытяжке, превышающей приток, модель добавляет наружный воздух для компенсации; для сбалансированных вентиляторов расход не учитывается дважды.

Расход открытого окна оценивается как `Q = 3600 · Cd · Aeff · sqrt(2·Δp/ρ)`, где `Δp` складывается из давления ветра `0.5·ρ·Cwind·v²` и температурного напора `ρ·g·H·|ΔT|/(2·Tmean)`. Эффективная площадь и максимальный расход ограничены коэффициентами `physics.toml`. Тепловая модель использует теплопередачу ограждений, тепловую инерцию комнаты, вентиляционный теплообмен и внутреннее тепло людей. Влажность рассчитывается через влагосодержание воздуха (отношение массы водяного пара к массе сухого воздуха), после чего переводится обратно в RH по насыщенному давлению пара.

Все коэффициенты находятся в `config/physics.toml`, параметры комнаты — в `config/room.toml`, характеристики вентиляторов и фильтра — в `config/devices.toml`. Исходная генерация CO₂ установлена в 0.30 л/мин на человека, то есть 0.005 л/с; это порядок величины для спокойной активности по [обзору NIST](https://www.nist.gov/publications/carbon-dioxide-generation-rates-building-occupants). Для конкретных людей значение зависит от возраста, телосложения и активности, поэтому коэффициент оставлен настраиваемым. Значения мощности вентилятора трактуются как оценка механической мощности на валу, а электрическая оценка делится на КПД; `total_relative_energy` складывает эту электроэнергию и вентиляционные теплопотери в Wh-эквиваленте.

Это лёгкая модель для демонстрации трендов, не CFD и не результат калибровки на конкретной комнате. Сейчас в ней нет отопления/кондиционирования, солнечного нагрева, многозонных потоков и измеренной аэродинамики окна. Поэтому теплопотери и энергия являются оценками, а коэффициенты нужно уточнять по реальному стенду перед использованием для проектных выводов.

## Проверки

В проекте используются тесты `aircheck_simulator_3d/tests`. Для них нужны зависимости из `aircheck_simulator_3d/requirements-dev.txt`. Полный тестовый запуск выполняется из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pytest aircheck_simulator_3d/tests -q
```

Milestone 3 не меняет существующие REST-контракты, dashboard, ML или старый simulator. Модель CO₂/PM/температуры/влажности и воздухообмена, а также backend-интеграция остаются будущими этапами. Сетевой слой M1 пока не активен.
