# AirCheck 3D Simulator

Отдельное Python-приложение цифрового двойника AirCheck. В нём есть интерактивный 3D-стенд оборудования, детерминированная инженерная модель комнаты и подключение виртуального ESP32 к существующему AirCheck backend.

## Запуск в Windows PowerShell

Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r aircheck_simulator_3d/requirements-dev.txt
.\.venv\Scripts\python.exe -m aircheck_simulator_3d
```

Короткая проверка старта и закрытия окна:

```powershell
.\.venv\Scripts\python.exe -m aircheck_simulator_3d --smoke-test-seconds 5
```

Для кириллических подписей используется системный TrueType-шрифт. Его путь задаётся в `config/graphics.toml` параметром `ui_font_path`.

## Управление сценой

| Управление | Действие |
|---|---|
| `W / A / S / D` | Плавное свободное перемещение относительно направления камеры |
| `Q / E` | Движение вниз / вверх по мировой вертикали |
| `Shift` | Ускорение перемещения |
| Зажать `ПКМ` и двигать мышь | Поворот камеры с захватом курсора |
| Колесо мыши | Плавный наезд / отъезд вдоль направления взгляда |
| `ЛКМ` | Выбрать объект сцены или снять выбор пустым щелчком |
| `F` | Плавно сфокусироваться на выбранном объекте |
| `R` | Вернуть камеру в начальную позицию |
| `C` | Переключить переднюю стену: видимая → прозрачная → скрытая |
| `O` / `K` | Подать локальную команду открыть / закрыть окно |
| `I` / `X` | Переключить локально приточный / вытяжной вентилятор |
| `V` | Включить / выключить фильтр притока |
| `Space` | Пауза / продолжить симуляционное время |
| `1`…`6` | Скорость времени: 1× / 2× / 5× / 10× / 30× / 60× |
| `Esc` | Освободить мышь и открыть подсказку; повторное нажатие продолжает работу |

На наведение указывает цветовой маркер курсора. Выбранный узел остаётся выделенным, а справа показывается его описание. Передняя стена в начальном режиме прозрачная, чтобы сразу был виден интерьер. Клавиши `O`, `K`, `I`, `X` и `V` оставлены как локальные тестовые команды; команды backend обрабатываются независимо через Device Layer. Краткие показания комнаты, погоды, окна, вентиляции и прогноза CO2 показаны в HUD слева.

## Демонстрация и интерактивные панели

### Меню и режимы вида

Верхняя полоса группирует управление симуляцией, сценарии и панель устройств. Статус backend остаётся видимым; инструменты открывают подробности сервера, отладку и справку, а отдельная кнопка ведёт в веб-панель. Нижняя сегментированная полоса выбирает `Обычный`, `Поток`, `Датчики`, `Проводка` и `Техника`. Режим `Поток` показывает струи от окна и вентиляторов; `Датчики` подсвечивает узлы датчиков, `Проводка` отображает кабельные трассы, а `Техника` объединяет технические слои. Интерфейс использует светлые поверхности и единый русский язык; снаружи стенда видны голубой фон неба и светлая зелёная площадка.

### Сценарии и AUTO DEMO

Меню `SCENARIOS` содержит `Normal Room`, `CO2 Buildup`, `High Occupancy`, `Clean Outdoor Air`, `Polluted Outdoor Air`, `Cold Weather`, `High Indoor PM2.5`, `Sensor Failure` и `Backend Offline`. Условия заданы в `config/demo.toml`; они обновляют текущее состояние Simulation Core и Device Layer. `Sensor Failure` отмечает SCD41 недоступным и приостанавливает публикацию неполных или недостоверных readings. `Backend Offline` включает оффлайн-статус для демо, не трогая реальный backend.

Кнопка `AUTO DEMO` готовит сценарий роста CO2 и ждёт новую телеметрию, прогноз, команду от backend, фактическое исполнение устройством, ACK и снижение CO2. Сценарий CO₂ buildup использует наружный ветер 3 м/с при закрытом окне для воспроизводимого проветривания после открытия створки. Simulator не создаёт команду сам; если backend или автоматика не выдаст команду, индикатор останется на этом шаге.

### Состояния устройств

Правая панель показывает данные выбранного узла. Страницы есть для ESP32, SCD41, обоих SPS30, SHT45, окна, привода, геркона, концевиков, обоих вентиляторов и силовых модулей. Текст панели получается из текущих состояний Simulation Core, Device Layer и backend. Панель `BACKEND` отображает online/offline, время последней принятой телеметрии, очередь команд, прогноз и имя ML-модели.

### Developer Panel

Панель `DEBUG` редактирует число людей, наружные CO2, PM2.5, температуру и RH, внутренний источник PM2.5, ветер, инфильтрацию, эффективность фильтра, расходы вентиляторов и sensor noise. Границы и шаги хранятся в `config/demo.toml`; рядом можно паузить симуляцию и перебирать её скорость.

При запуске приложение подключается к backend из `config/backend.toml`. Оно публикует телеметрию в `/api/v1/measurements`, забирает команды из `/api/v1/controls/commands` и отправляет фактическое состояние в `/api/v1/controls/state` — по тем же REST-контрактам, что и старый simulator. Идентификатор берётся из `config/devices.toml` (`DEVICE_ID` может его переопределить).

HTTP выполняется в одном фоновом сетевом потоке, а отправка телеметрии, опрос команд, ACK и health-проверка разделены по компонентам. При недоступности сервера физическая модель и сцена продолжают работать; статус backend виден в правой панели. После восстановления соединения отправляются последнее измерение и ожидающие ACK. Телеметрия во время offline сводится к последнему снимку, чтобы не отправлять устаревшие значения пачкой. Команда окна остаётся активной до достижения нужного концевика и остановки мотора; ACK содержит фактические состояния устройств. Прогноз CO₂ берётся из ответа backend/последнего измерения и не рассчитывается внутри simulator. Кнопка «Открыть панель AirCheck» использует `dashboard_url`; если поле пустое, открывается `backend_url`.

Сетевые интервалы, таймаут и повторы задаются в `config/backend.toml`: `telemetry_interval_seconds`, `command_poll_interval_seconds`, `health_check_interval_seconds`, `request_timeout_seconds`, `retry_attempts` и `retry_base_delay_seconds`. Интервалы также можно переопределить переменными окружения `SIMULATOR_INTERVAL_SECONDS`, `COMMAND_POLL_INTERVAL_SECONDS` и `BACKEND_HEALTH_CHECK_INTERVAL_SECONDS`.

## Архитектура приложения

- `scene/scene_builder.py` строит основание, пол, потолок, стены и наружную площадку, затем подключает сборку оборудования.
- `scene/device_models/` независимо собирает створку и привод, внутренние и наружные датчики, оба вентиляционных канала, технический шкаф и кабельные трассы из процедурной low-poly геометрии.
- `devices/window_actuator.py` и `devices/device_layer.py` владеют фактическим положением окна, мотором, герконовым состоянием, концевиками и состояниями вентиляторов.
- `app/runtime.py` обрабатывает локальные тестовые команды, переносит команды из сетевой очереди в Device Layer и публикует снимки состояния; `simulation/engine.py` выполняет фиксированные шаги независимо от render FPS.
- `networking/http_backend.py` реализует только фактические AirCheck REST-маршруты; `networking/workers.py` разделяет отправку telemetry, опрос команд, ACK и health-проверку, не обращаясь к Panda3D или состоянию сцены из фонового потока.
- `devices/command_executor.py` сериализует команды одного исполнительного устройства и сообщает о выполнении после проверки фактического состояния; решение об автоматике остаётся на стороне backend.
- `simulation/room_model.py` рассчитывает воздухообмен, CO₂, PM2.5, температуру, относительную влажность и оценку энергии; 3D-слой получает только состояния устройств для отображения.
- `presentation/device_bindings.py` отражает фактический угол створки, индикаторы концевиков и вращение включённых вентиляторов; модели не содержат бизнес-логики.
- Провода различают питание (+12/+5 V), GND, связь датчиков (I²C/UART) и управление исполнительными устройствами. Это визуальная схема подключения, а не электрический CAD.
- `scene/objects.py` содержит процедурную геометрию и единый реестр интерактивных объектов.
- `scene/cutaway.py`, `scene/picking.py` отдельно управляют состоянием стены и raycast-выбором.
- `scene/lighting.py` настраивает ambient и directional light; при доступности драйвера включает карту теней.
- `presentation/camera_controller.py` отвечает за плавное перемещение, обзор мышью, наезд, фокус и сброс камеры.
- `presentation/input_controller.py` связывает действия клавиатуры и мыши с компонентами представления.
- `presentation/viewport.py` собирает слои, обновляет viewport и пишет оценку FPS при завершении.
- `ui/scene_overlay.py` собирает меню, HUD, live-панель устройств, сценариев, backend и Developer Panel.
- `presentation/airflow_visualization.py` рисует потоки по фактическим расходам модели, положению окна и состоянию вентиляторов.
- `config/room.toml`, `devices.toml` и `physics.toml` задают начальные условия и коэффициенты модели; `scene.toml`, `camera.toml` и `graphics.toml` описывают стенд, камеру и освещение.

Передняя стена отключает свою collision-маску в прозрачном и скрытом режимах, чтобы луч выбора проходил к объектам комнаты. Геометрия сделана процедурными кубами без дополнительных 3D-ресурсов.

Panda3D использует стандартные материалы с диффузным и зеркальным откликом, MSAA при доступности framebuffer и встроенные shadow maps. Модели оборудования процедурные и достаточно детализированы для архитектурной демонстрации, но не являются производственными CAD-моделями. Вращение вентилятора следует за состоянием устройства. Если драйвер не предоставляет MSAA, приложение продолжает работу без него.

## Математическая модель помещения

Среда считается однозонной и хорошо перемешанной. При расходах воздуха `Q` в м³/с и объёме `V` в м³ используются балансы:

```text
CO₂:      dC/dt = G/V + Q/V · (Cout - C)
PM2.5:    dP/dt = Sin/V + Σ(Qin · Cin)/V - (Qout/V + kdep) · P
Тепло:    Cth · dT/dt = (UA + ρ·cp·Q) · (Tout - T) + N · Hperson
Влага:    dw/dt = Gw/m_air + Q/V · (wout - w)
```

CO₂, PM2.5 и влагосодержание интегрируются точным решением баланса первого порядка за каждый фиксированный шаг: источники добавляют массу/концентрацию, воздухообмен стремит её к наружному значению, а фильтр уменьшает только наружную PM2.5 в приточном канале. При вытяжке, превышающей приток, модель добавляет наружный воздух для компенсации; для сбалансированных вентиляторов расход не учитывается дважды.

Расход открытого окна оценивается как `Q = 3600 · Cd · Aeff · sqrt(2·Δp/ρ)`, где `Δp` складывается из давления ветра `0.5·ρ·Cwind·v²` и температурного напора `ρ·g·H·|ΔT|/(2·Tmean)`. Эффективная площадь и максимальный расход ограничены коэффициентами `physics.toml`. Тепловая модель использует теплопередачу ограждений, тепловую инерцию комнаты, вентиляционный теплообмен и внутреннее тепло людей. Влажность рассчитывается через влагосодержание воздуха (отношение массы водяного пара к массе сухого воздуха), после чего переводится обратно в RH по насыщенному давлению пара.

Все коэффициенты находятся в `config/physics.toml`, параметры комнаты — в `config/room.toml`, характеристики вентиляторов и фильтра — в `config/devices.toml`. Исходная генерация CO₂ установлена в 0.30 л/мин на человека, то есть 0.005 л/с; это порядок величины для спокойной активности по [обзору NIST](https://www.nist.gov/publications/carbon-dioxide-generation-rates-building-occupants). Для конкретных людей значение зависит от возраста, телосложения и активности, поэтому коэффициент оставлен настраиваемым. Значения мощности вентилятора трактуются как оценка механической мощности на валу, а электрическая оценка делится на КПД; `total_relative_energy` складывает эту электроэнергию и вентиляционные теплопотери в Wh-эквиваленте.

Это лёгкая модель для демонстрации трендов, не CFD и не результат калибровки на конкретной комнате. Сейчас в ней нет отопления/кондиционирования, солнечного нагрева, многозонных потоков и измеренной аэродинамики окна. Поэтому теплопотери и энергия являются оценками, а коэффициенты нужно уточнять по реальному стенду перед использованием для проектных выводов.

## Проверки

В проекте используются тесты `aircheck_simulator_3d/tests`. Для них нужны зависимости из `aircheck_simulator_3d/requirements-dev.txt`. Полный тестовый запуск выполняется из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pytest aircheck_simulator_3d/tests -q
```

Сетевые сообщения записываются в `network.log`; команды подтверждаются после сверки actual state Device Layer. Долгие accelerated-тесты проверяют одни сутки и семь суток моделируемого времени, а тест Automatic Demo проверяет, что пустые обновления не сбрасывают этап ACK.

## Частоты и профили качества

Рендер ограничен `target_fps` (по умолчанию 60), Simulation Core работает фиксированным шагом 0,1 с (10 Гц), UI обновляется каждые 0,1 с (10 Гц), Network Layer использует собственный поток и интервалы из `config/backend.toml`. Изменение FPS не меняет физический timestep.

В `config/graphics.toml` доступны `quality_preset = "low"`, `"medium"` и `"high"`; при запуске профиль можно переопределить через `--quality low|medium|high`. Low отключает тени и MSAA, Medium включает 2x MSAA и тени 512 px, High использует 4x MSAA и тени 1024 px. При отсутствии поддержки MSAA приложение запускается без него.

## Standalone Windows-сборка

Для сборки нужен 64-битный Python 3.12:

```powershell
.\.venv\Scripts\python.exe -m pip install -r aircheck_simulator_3d/requirements-dev.txt
.\scripts\build-windows.ps1
.\scripts\smoke-windows-build.ps1
```

Сборка и runtime лежат в `build/win_amd64/`; переносить нужно каталог целиком. В standalone-режиме журналы сохраняются в `%LOCALAPPDATA%\AirCheck3D\logs`, журнал Panda3D — в `%LOCALAPPDATA%\AirCheck3D\panda.log`.
