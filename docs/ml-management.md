# Управление ML-моделью

В технической вкладке настроек владелец выбирает источник и запускает обучение. Просмотр состояния и метрик доступен пользователям панели; обучение и возврат версии проверяются сервером и разрешены только owner.

Сгенерируйте отдельный `ML_MANAGEMENT_TOKEN` длиной не менее 32 символов и задайте одинаковое значение в backend и ML. Для локальных процессов экспортируйте его обоим сервисам; Compose передаёт значение из `.env`. Не используйте device token для этой задачи. Токен не выдаётся браузеру. Без него прогнозирование продолжает работать, а панель объясняет отсутствие настройки управления.

ML сохраняет `training-job.json`, активный `model.joblib`, `previous.joblib` и lock в постоянном каталоге `MODEL_PATH`. Один процесс держит межпроцессную блокировку на всю задачу/откат. Состояния: queued, running, succeeded, failed. При перезапуске прерванная задача становится failed; действующая модель сохраняется. Кандидат строится в отдельном временном каталоге, проверяется и заменяет активный файл через atomic rename. Откат меняет активную и предыдущую версии местами. Ошибка и недостаточная история не меняют активный артефакт.

Источники real / simulator / unknown не смешиваются в обучении, признаках и эксплуатационной оценке. Оба симулятора объявляют simulator; старые устройства без поля остаются unknown. Источник заявляет доверенное устройство, аппаратной проверки происхождения пока нет.

Модель прогнозирует на 15 минут. Train/test — временное разделение 80/20 с исключением обучающих строк, чьи целевые измерения попадают в test-период. Отчёт показывает исключённые строки, фактические границы, train/test count, MAE/RMSE каждой модели и выбранную модель. Минимум валидных строк задаётся `MIN_TRAINING_ROWS` (30 по умолчанию); дополнительно нужны минимум две независимые train-строки после исключения.

Качество эксплуатации считается отдельно: ближайшее фактическое измерение того же источника ±60 секунд от цели, только прошедшие цели и измерения. Показаны число пар и метрики по источнику/версии за доступные сырые данные. Отсутствие пар не означает нулевую ошибку. Это не оценка на новых реальных данных, если источник simulator или unknown.

CLI `train.py` использует тот же механизм. Для смешанной входной истории обязательно `--data-source`; `--output-dir` выбирает постоянный каталог. Онлайн-сервис подхватывает изменение артефакта без перезапуска.
