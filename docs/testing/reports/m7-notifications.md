# M7 — журнал событий и Telegram

Добавлены устойчивые эпизоды превышения CO₂, потери связи, неисполненных команд и восстановления. Настраиваются длительность и подавление повторов; продолжающаяся проблема порождает одно событие. Неактуальное измерение не считается восстановлением CO₂. Состояния и журнал сохраняются в PostgreSQL; фоновые проверки запускаются при старте backend без открытой панели. Журнал хранится 90 дней, отметки прочтения индивидуальны.

Владелец настраивает Telegram и явно выбирает сохранённый чат для проверки. Токен зашифрован AES-256-GCM, не возвращается API; сообщения ошибок доставки не содержат адреса с токеном. Доставка отделена от управления: ограничена тремя попытками, использует lease для восстановления после остановки процесса и показывает результат в журнале. Изменение канала отменяет неподходящие ожидающие сообщения. Без Telegram журнал работает самостоятельно.

Проверки: 394 frontend-теста, 282 Python/PostgreSQL-теста, typecheck и production build прошли. Браузерный E2E на изолированной базе проверил все предыдущие milestones и новый функционал: CO₂/command/offline, дедупликацию, восстановление, разные read marks пользователей, owner/operator/anonymous права, шифрование и удаление токена. Контролируемый локальный транспорт подтвердил успех третьей попытки после двух ошибок и окончательный отказ после трёх ошибок; бесконечной очереди нет. Настройки и журнал проверены на 1920/1440/1024/768/390/320 px, клавиатурой; mobile screenshot просмотрен. Реальные сообщения в Telegram не отправлялись.

Дополнительный Compose-набор запускался отдельно: четыре проверки остановились на подготовке стенда, до выполнения сценариев. После переноса Docker config в доступный каталог сборка дошла до установки зависимостей, но DNS внутри контейнера не разрешил адрес Python registry. Проверка через контейнер с host network также не разрешила `pypi.org`. Это ограничение сети данной среды; контейнерная сборка целиком не подтверждена. Нативная production-сборка, реальные PostgreSQL, ML, simulator и браузерные сценарии прошли.

После финального форматирования новых TypeScript-файлов повторно прошли typecheck, 394 frontend-теста и production build. Постоянная облачная база обновлена всеми миграциями без удаления volume; собственные backend/ML/simulator перезапущены и прошли health-check. PostgreSQL подтвердил обновление фоновых notification conditions без открытой панели. Startup/install инструкции сохранены в draft среды; сохранение не является публикацией.

Ограничения: доставка имеет семантику at-least-once — остановка между приёмом Telegram и сохранением результата может дать повтор. Очередь и сеть ограничены; журнал не обещает получение сообщения пользователем. Отдельный ключ шифрования рекомендуется для независимой ротации; смена ключа требует повторного сохранения токена.
