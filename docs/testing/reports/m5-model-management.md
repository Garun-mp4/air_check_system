# M5 — управление и оценка модели

Owner-панель запускает фоновое обучение по выбранному источнику и возвращает предыдущую модель. Добавлены статусы задач, версия/дата/диапазон, train/test count и MAE/RMSE. Межпроцессная блокировка запрещает одновременные изменения; проверенный кандидат активируется атомарно. Ошибка сохраняет рабочую модель, прерванная перезапуском задача становится failed. CLI использует тот же механизм и отклоняет смешанные источники без явного выбора.

Телеметрия и прогнозы сохраняют real/simulator/unknown; старые данные не объявляются реальными. Источники разделены в обучении, признаках и метриках эксплуатации. Из train исключены цели, попадающие в test-период. Метрики эксплуатации считают ближайшую фактическую точку того же источника ±60 секунд; будущие цели/измерения исключены.

Проверки: 373 frontend-теста, 277 Python/PostgreSQL-тестов, typecheck и production build прошли. Отдельно проверены конкуренция, ошибочная задача, перезапуск, атомарная активация/откат, отсутствие утечки будущих labels, защита внутренних management routes и upgrade неизвестного источника. Окончательный реальный браузерный набор прошёл: owner train, operator denied, новый прогноз использует новую версию, недостаточная история не меняет модель, rollback; SQL-фикстура метрик даёт ровно одну пару с MAE/RMSE 100, неподходящие источники/времена и будущая цель исключены. Шесть ширин панели без переполнения; мобильный screenshot просмотрен.

Ограничения: происхождение заявляет доверенное устройство; метрики эксплуатации ограничены сроком хранения сырых данных. Четыре опциональных Compose-теста пропущены. Для управления нужен отдельный ML_MANAGEMENT_TOKEN и постоянный writable каталог модели; это документировано в [ml-management.md](../../ml-management.md).
