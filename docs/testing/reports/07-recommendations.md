# Отчёт: блок 07 — рекомендации и серверная бизнес-логика качества воздуха

## Сверка контракта и текущего покрытия

Сверены `docs/api.md`, `docs/ТЗ-поправка-03-climate-control.md`, `frontend/src/server/recommendation.ts`, `settings.ts`, `features.ts`, `service.ts`, `control-service.ts` и существующий `frontend/src/server/server.test.ts`.

API указывает, что сохранённые пороги узла применяются к рекомендациям и автоматике. Поправка климатического контура задаёт включительное критическое условие: при текущем или прогнозируемом CO₂ не ниже `CO2_CRITICAL_THRESHOLD` автоматика открывает окно и включает оба вентилятора. Она также требует поддержки обоих каналов при открытом окне и CO₂ выше нормального порога; закрытие после восстановления CO₂ допускается только после минимального времени проветривания.

Существующие тесты уже покрывают базовые рекомендации при высоком CO₂, прогнозное предупреждение, PM2.5-пороги и выключенные PM-оповещения, обновление настроек узла, критическое автоматическое проветривание, ручной режим, ручной вентилятор и закрытие после минимального времени. Новые проверки не повторяют подготовку ML-признаков из блока 06.

## Добавленные проверки

Новый файл `frontend/src/server/recommendation-business-logic.test.ts` содержит 13 проверок:

- классификация CO₂ немного выше нормального порога и выше критического порога при одновременно более низком прогнозе;
- indoor PM2.5 немного ниже и выше заданного нормального предела;
- разница между отсутствующим и доступным прогнозом при текущем CO₂ ниже нормального порога;
- применение сохранённых CO₂/PM2.5-порогов и `alertsEnabled` в цепочке `AirQualityService.ingest`;
- отсутствие автоматических команд при PM2.5-оповещении и нормальном CO₂;
- автоматический пакет из окна и обоих вентиляторов при точном критическом пороге как в измерении, так и в прогнозе;
- включение обоих каналов при открытом окне и CO₂ выше нормального порога;
- отсутствие новой команды после подтверждения работающей автоматической вентиляции;
- отсутствие команд при нормальном CO₂ и выключенном контуре;
- одинаковая рекомендация при одинаковых входных данных.

## Вопросы спецификации

- Поправка явно задаёт `CO₂ >=` для критического автомата, но не фиксирует, считается ли равенство нормальному порогу превышением в рекомендациях. Для PM2.5 также не определено, относится ли точное равенство к нормальной или повышенной категории. Новые boundary-проверки используют значения по обе стороны предела; равенство проверяется только для критического автоматического условия, описанного как «не ниже».
- API принимает наружный PM2.5 отдельно от внутреннего, но документы не определяют, должно ли высокое наружное значение менять совет по окну или притоку. Тесты проверяют внутренний PM2.5; они не закрепляют политику по наружному воздуху.
- Назначение `alerts_enabled` подробно не определено. Проверено его текущее использование для PM2.5-оповещения; влияние на CO₂-рекомендации не фиксируется новым тестом.
