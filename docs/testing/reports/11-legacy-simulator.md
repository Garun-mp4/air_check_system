# Блок 11 — Старый REST-only sensor-simulator

## Объём и границы

Добавлены четыре уникальных файла тестов в `sensor-simulator/tests/`. Production-код, lease logic, общие fixtures, pytest-конфигурация и продуктовые Docker/config файлы не менялись.

Новые тесты проверяют конечный JSON measurement payload и нормализацию aware timestamp к UTC `Z`; воспроизводимость последовательности сценария для одинакового seed; количество и повторяемость backfill-публикаций при замороженном времени; запрос polling, применение валидных команд, отражение состояний в measurement и `POST /controls/state` с `applied_command_ids`; продолжение live-цикла при недоступности polling; retry HTTP/network errors, timeout, настраиваемое количество попыток и exponential delays; а также взаимоисключение legacy и headless lease из двух отдельных процессов для одного `DEVICE_ID`.

HTTP-клиентские вызовы подменяются в unit-тестах. Сервер backend, внутренние headless routes и полный Compose не запускаются: проверка не заменяет сетевые/service тесты блока 10 или full Compose E2E блока 14. Межпроцессная lease-проверка запускает локальные процессы Python и работает с временной директорией.

Среда: Windows 11, CPython 3.12.10 (`C:\Users\admin\AppData\Local\Programs\Python\Python312\python.exe`), pytest 8.3.5. Использованы установленные локальные зависимости; новые пакеты и окружения не создавались.

## Вопросы к неопределённому контракту

- Документация говорит, что backfill заполняет историю и принимает количество точек и интервал, но не определяет точную временную границу ряда, включение текущего момента, поведение при ошибке отправки одной точки или гарантии порядка сохранения. Тесты проверяют переданное число публикаций и повторяемость для одного seed и фиксированного времени; конкретную политику временных меток и частичного отказа не закрепляют.
- Документация описывает retry с exponential backoff, но не определяет retry policy для polling команд и отправки actual state, классы HTTP-кодов для повтора, jitter/верхнюю задержку либо восстановление после исчерпания попыток. Тесты закрепляют существующее поведение `post_measurement` при HTTP 503, сетевой ошибке и timeout с заданными параметрами; решения по остальным операциям требуют явного контракта.
- Сервер API помечает команду applied только при совпадении desired state и переданного фактического boolean. Новые unit-тесты подтверждают, что legacy simulator посылает актуальные состояния и `applied_command_ids`; принятие/отклонение ACK сервером относится к отдельным API/integration проверкам.
- Lease-тест подтверждает конфликт между двумя процессами, использующими lease-модули legacy и headless, с одним каталогом и `DEVICE_ID`. Запуск сервисов через Compose и проверка общего volume относятся к блоку 14 и здесь не выполнялись.
